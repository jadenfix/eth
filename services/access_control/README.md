# Access control and local security primitives

Run `PYTHONPATH=. python -m unittest discover -s tests/access_control -v` from the repository root. This executes actual policy evaluation, SQLite persistence/deletion, hash-chain integrity checks and Fernet encryption. It needs `cryptography`, `structlog` and `PyYAML`; cloud SDKs are initialized only by the cloud PolicyEngine/AuditSink constructors.

`PolicyEvaluator(policies, identities)` requires explicit rules and an authenticated server-side principal-to-role mapping. It denies unknown principals, missing context, partial column authorization and unmatched actions/resources. Rules use one scalar comparison per condition; executable expressions are rejected. Role claims in request context do not authorize access. The original PolicyEngine also uses explicitly provisioned exact identities, denies unknown restrictions, records denied requests, and denies access when required audit publishing fails. A provider rejection nacks the original AuditSink message instead of acknowledging lost audit data.

`AuditLogger(path, evaluator, provider)` persists records transactionally in SQLite, masks known secret/PII metadata fields, and verifies its hash chain before reading. An optional remote provider failure propagates after local durability. A hash chain alone does not protect against whole-database destruction or a privileged rewrite; externally anchor journal digests for stronger evidence. Configure a protected persistent path; local files are not a SOC 2 certification.

`DataMasker` masks explicitly known PII fields recursively, preserving public blockchain identifiers. This is field-based masking, not automatic DLP. Its admin bypass must be supplied only by trusted authorization code.

`SanctionsChecker(addresses, source, as_of)` requires an explicit dated source, supports case-insensitive Ethereum-address matching, and returns `is_sanctioned: null`, `blocked: true`, `status: unavailable` when no source exists. A nonmatch means only that an address is not in that supplied list, not a current legal compliance determination. There is no bundled historical-address list or invented program label. Source retrieval, freshness and coverage are operator responsibilities.

`DataEncryption(key)` uses authenticated Fernet encryption and rejects wrong keys or modified ciphertext. Generate keys with `generate_key()` and retain them securely across process restarts; no key is silently generated for persistent data. `GDPRCompliance(path)` exports/deletes actual records in its explicit local subject database. Its scope excludes immutable blockchain data, retained audit records and other deployed processors; its class name is not an assertion of system-wide legal compliance. Authenticate and authorize subject operations before invoking it.

Legacy test assumptions require explicit fixtures: load the policy a test defines; provide a fixture sanctions list with provenance rather than certifying unknown addresses clean; provide an encryption key; and insert records into an explicit subject database before asserting deletion. Offline tests verify these boundaries without substituting success for absent external infrastructure.
